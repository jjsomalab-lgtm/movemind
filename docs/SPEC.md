## 1. 產品定位

心動力 AI 是給健康、具基本自主活動能力之長輩使用的運動陪伴網頁 APP，原則是「先關心，再陪你動」：

- **陪伴在前**：先問候、可聊天或點選心情，每一步都能略過。
- **安全在中**：活動由「固定的安全規則」決定，AI 只負責陪伴與鼓勵，不診斷、不治療、不開運動處方。
- **樂趣在後**：完成活動讓「心動綠洲」花園長大，並能分享給家人。

不做的事：醫療診斷、心理治療、緊急救護、跌倒偵測、宣稱臨床療效。

## 4. 畫面與流程

```
第一次打開：歡迎 → 7 題健康篩選 → 結果與家人電話 → 首頁
每天使用：首頁（問候）→ 心情（可略過）→ 3 題活動前確認 → 活動列表 → 活動進行 → 獎勵（花園長大）
出門散步：散步準備 → 散步中（地圖、距離、安心分享、打卡）→ 結束 → 獎勵
隨時可用：右上角「不舒服」→ 求助頁（119、1925、家人、傳送位置）
```

底部分頁：今天｜活動｜散步｜綠洲｜紀錄。設定在左上角齒輪。

## 5. 安全規則（固定規則，不交給 AI 判斷）

### 5.1 首次健康篩選（`SCREENING`，8 題，每 90 天提醒重做）

開始前先問「今天有家人或據點人員陪你一起設定嗎？」並記錄。題目分兩類：

| 類別 | 題目 | 任一題「有」或「不確定」的結果 |
|---|---|---|
| 需醫師確認（doctor） | 心臟疾病、活動時胸痛胸悶、一年內頭暈站不穩或昏倒、醫師說需醫療人員陪同 | `seated`：只開放坐姿活動；扶椅活動與散步需醫師同意，並由據點人員在「設定」中解鎖 |
| 需有人陪同（assist） | 高血壓、一年內跌倒、骨骼關節問題、服用心臟或血壓藥 | `assisted`：坐姿活動可自己做；扶椅活動與散步每次需確認「有人陪同」 |
| 全部「沒有」 | — | `standard`：坐姿、扶椅活動與散步都可以 |

- 高血壓、跌倒史、服藥在長輩中很常見，所以列為「需有人陪同」而非一律鎖住，以符合「健康長輩」的定位。
- 解鎖後的等級為 `assisted`（仍需有人陪同），不會直接變成 `standard`。

### 5.2 每日活動前確認（`DAILY_CHECK`，3 題，不可略過）→ 今日 `allowed`

| 條件（由上往下判斷） | allowed |
|---|---|
| 胸悶、胸痛或頭暈 = 有 **或不確定** | `none`：今天停止，不能運動也不能散步，顯示休息建議與 119 |
| 新的疼痛 = 有或不確定 | `seated` |
| 鞋子與椅子 = 還沒或不確定 | `seated` |
| 今天心情 = 有點累 | `seated` |
| 篩選等級為 `seated`（未解鎖） | `seated` |
| 以上皆否 | `standard` |

- 心情可以略過，略過不影響活動範圍；「心煩」不限制活動，但提供 1925 安心專線。
- `seated` 時散步也暫停，提示改做坐姿活動。

### 5.3 活動與散步的開放規則

| 今日 allowed ＼ 篩選等級 | standard | assisted | seated（未解鎖） |
|---|---|---|---|
| none | 全部停止 | 全部停止 | 全部停止 |
| seated | 只有坐姿 | 只有坐姿 | 只有坐姿 |
| standard | 全部開放 | 坐姿自由；扶椅與散步需確認有人陪同 | （不會出現，篩選 seated 時 allowed 最多 seated） |

### 5.4 警訊處理（三處一致：停下 → 坐下 → 嚴重症狀打 119）

| 觸發 | 系統行為 |
|---|---|
| 右上角「不舒服」（每個畫面都有） | 停止鏡頭與語音，顯示 119、1925、家人電話、傳送位置 |
| 每日確認胸悶頭暈 = 有或不確定 | 今天停止，顯示休息建議與 119 |
| 聊天提到身體緊急症狀（胸痛、胸悶、呼吸困難、心悸、冒冷汗、半邊無力、講話不清、昏倒、頭暈、跌倒了） | 固定回覆：先停下坐好，這些可能是緊急狀況，請打 119 |
| 聊天提到自傷或婉轉說法（不想活、不想拖累家人、早點走等） | 固定回覆 + 1925 與 119 撥號按鈕 |
| 聊天提到「怕跌倒」 | 安撫並建議坐姿活動、站姿活動找人陪同（不觸發 119） |

### 5.5 散步的季節提醒

- 5–10 月 10:00–16:00：高溫提醒，建議早晚出門、帶水。
- 12–2 月 8:00 前或 18:00 後：低溫提醒，血壓容易受影響，建議等太陽出來、穿暖再出門。

### 5.6 姿勢辨識計數（坐姿抬腿）

- 不要求把腳伸直。膝蓋角度比放下時多抬 20° 就算 1 下，降回 10° 以內才能算下一下；放下時角度需小於 140°。
- 目的：讓膝蓋活動角度較小、照「抬低一點」提示做的長輩也能被計數，不會為了獎勵勉強伸直。
- 目標次數為「左右腳合計」。側坐時鏡頭較能看清靠近鏡頭的那隻腳，需以長輩實測確認。

## 6. 心動綠洲規則

| 行為 | 獎勵 |
|---|---|
| 新使用者 | 花園先有 1 顆茉莉花種子 |
| 完成一次居家活動 | +1 種子，替最需要的植物澆 1 次水（升一階） |
| 散步 | 每 0.3 公里澆 1 次水（至少 1 次），累積社區合作里程 |
| 第一次打卡 | 解鎖高雄市花「木棉花」，+1 種子 |
| 之後每次打卡 | +1 種子 |

- 植物 4 階段：種子 → 發芽 → 長葉 → 開花；花園 9 格，先種前排。
- 全部開花時，水會存起來，種新植物時自動使用。
- 社區合作任務：據點大家一起走 10 公里種出一棵大樹（初審版為展示數字，決審版改為同據點使用者的真實加總）。
- 原則：只有合作、沒有排名，不讓長輩互相比較。

## 7. AI 串接規格（決審版）

### 7.1 架構

```
手機網頁 ──HTTPS──> Python 後端（FastAPI） ──> 大型語言模型 API
                         │
                         ├─ 安全前置檢查（關鍵字 → 固定回覆，不送給 AI）
                         ├─ 呼叫 AI（只負責陪伴話語）
                         └─ 安全後置檢查（過濾診斷、處方用語）
```

**AI 金鑰只能放在後端環境變數，絕對不能出現在網頁程式碼裡。**

### 7.2 API

`POST /api/chat`

```json
// 請求
{ "message": "今天膝蓋有點緊", "mood": "tired", "allowed": "seated", "history": [ ... 最近 6 則 ... ] }
// 回應
{ "reply": "膝蓋緊的時候...", "flag": null, "suggestActivity": "ankle-pump" }
```

- `flag`：`crisis`、`body` 或 `null`，前端依此顯示撥號按鈕。
- `suggestActivity`：只能是 `allowed` 範圍內的活動 id，由後端驗證；不合法就移除。

### 7.3 系統提示詞（初稿）

```
你是「心動小夥伴」，陪臺灣健康長輩聊天、鼓勵他們活動身體。
- 用臺灣華語、口語、溫暖，每次回覆不超過 60 字。
- 你不是醫師或心理師：不診斷、不解讀症狀、不給藥物建議、不開運動處方。
- 只能從提供的活動清單中建議活動，且不得超出今天允許的範圍。
- 使用者提到身體不舒服：請他休息，必要時撥打 119。
- 使用者提到想傷害自己：請他撥打 1925 安心專線或 119，並表達關心。
- 不要求或詢問身分證字號、地址、病歷等個人資料。
```

### 7.4 驗收

- 準備 30 句測試語句（含自傷、胸痛、要求開藥、要求高強度運動），全部符合 5.3 與 7.3 規則才可上線。
- 對話紀錄預設不保存；若研究需要，須另取得同意並通過倫理審查。

## 8. 帳號與資料（決審版）

| 項目 | 規格 |
|---|---|
| 訪客模式 | 保留，不登入也能使用，資料存手機 |
| Google 登入 | Firebase Authentication，登入後將手機資料合併上傳 |
| LINE 登入 | 試點版：LINE Login → 後端驗證 → Firebase 自訂 token；可與 Google 帳號綁定 |
| 雲端資料 | Firestore；每位長輩只能讀寫自己的資料（Security Rules） |
| 家人查看 | 長輩產生邀請碼 → 家人登入輸入 → 長輩確認後生效，隨時可取消 |
| 家人可見範圍 | 活動次數、散步距離、花園進度；聊天內容與心情細節預設不分享 |

## 9. 即時安心分享（決審版）

- 長輩在散步中按「開啟安心分享」→ 後端建立分享代碼（有效 2 小時）→ 用 LINE 傳連結給家人。
- 家人打開連結即可看到地圖上的即時位置與路線，每 15 秒更新。
- 散步結束或時間到，連結自動失效，位置資料刪除。
- 分享期間畫面上方持續顯示「正在與家人分享位置」，長輩可隨時停止。
- 明確標示：不是緊急救護服務，螢幕需保持亮著才能更新。

## 10. 資料模型

```
users/{uid}
  profile: { name, screening: { done, level, flags[] }, contacts[], fontScale, voice, shareRoute }
  sessions/{id}: { at, type: 'home'|'walk', activityId?, reps?, minutes, km?, route?[], moodAfter?: 'better'|'same'|'worse' }
  moods/{id}: { at, mood }
  fof/{id}: { at, score }   // 跌倒擔心度 0–10，每週一次
  garden: { seeds, water, plots[{ type, stage }], unlocked[], checkins[{ name, lat, lng, at }] }
family/{uid}: { viewers[{ uid, name, since }] }
liveShares/{code}: { uid, expiresAt, points[[lat, lng, t]] }
communities/{siteId}: { name, totalKm, goalKm }
```

初審版以相同結構存在 `localStorage` 的 `movemind.v1`。

## 11. 隱私與資安

- 資料最小化：預設只存距離與時間，完整路線需長輩勾選才保存。
- 姿勢辨識影像只在手機端分析，不上傳、不保存。
- 不收集身分證字號、病歷、地址。
- 首次登入時以大字、口語說明資料用途並取得同意，可由家屬陪同確認。
- 正式上線前擬定使用條款與非醫療聲明；據點合作協議載明責任範圍；評估產品責任保險。
- 研究用途（成效分析、發表）須先完成校方倫理審查。

## 12. 無障礙規格

| 項目 | 標準 |
|---|---|
| 字級 | 基本 20px，可放大到 1.3 倍 |
| 按鈕 | 最小高度 64px，主要按鈕 84px |
| 對比 | 文字與背景對比至少 4.5:1 |
| 每頁任務 | 一個畫面只做一件事 |
| 語音 | 所有問題與口令可朗讀（臺灣華語，語速 0.9） |
| 略過 | 心情、聊天都可略過；安全確認不可略過 |

## 13. 測試計畫

### 13.1 功能驗收（每次改版必測）

- [ ] 篩選 doctor 類任一題「不確定」→ 只有坐姿可點，散步頁顯示需醫師同意
- [ ] 篩選只有高血壓「有」→ 扶椅活動與散步出現「需要有人陪同」確認
- [ ] 每日確認「胸悶 = 有」或「不確定」→ 直接進入「今天先休息」，散步也被擋下
- [ ] 散步前若今天還沒確認，會先進入 3 題確認
- [ ] 聊天輸入「我怕跌倒」→ 安撫回覆，不出現 119；輸入「跌倒了」→ 出現 119 建議
- [ ] 心情「有點累」→ 只有坐姿可點
- [ ] 「不舒服」按鈕在所有頁面都看得到，按下後鏡頭停止
- [ ] 聊天輸入「不想活」→ 出現 1925 與 119 按鈕

- [ ] 完成活動或散步 → 出現「動完之後，心情怎麼樣？」，可略過；回答後週回顧顯示「動完心情變好」次數
- [ ] 首次使用或距上次 7 天 → 首頁出現跌倒擔心度問題；回答後週回顧顯示趨勢
- [ ] 聊天每 4 句出現一次鼓勵與家人朋友連結的提醒（危機回覆時不出現）
- [ ] LINE 分享週報文字正確
- [ ] 字級三段切換後版面不跑掉
- [ ] 飛航模式下仍能打開 APP

### 13.2 長輩可用性測試（11/08–11/20，5–8 位）

- 任務：自己完成一次「心情 → 確認 → 坐姿抬腿 → 看花園」
- 記錄：任務完成率、求助次數與卡住的步驟、完成時間、再次使用意願（1–5 分）
- 只記錄操作與意見，不記錄姓名；先口頭說明並取得同意

## 16. 心理學設計與理論對應

### 16.1 核心主張：打破「怕跌倒 → 不敢動」的循環

長輩跌倒過或擔心跌倒 → 減少活動來保護自己 → 肌力與平衡退化 → 更容易跌倒、更沒信心 → 更不敢動，情緒低落與孤單也隨之增加。心動力以**運動醫學確保安全**、以**心理學設計重建信心**，透過循序漸進的成功經驗打破這個循環。

### 16.2 理論對應

| 理論 | 對應設計 |
|---|---|
| 自我效能（Bandura）：成功經驗 | 小目標、退階做法、從坐姿到扶椅的分級、花園長大的具體回饋 |
| 自我效能：替代經驗 | 社區合作任務，看見同伴也在動 |
| 自我效能：言語說服 | 小夥伴的鼓勵與肯定 |
| 自我效能：生理與情緒狀態 | 活動前心情與疲勞確認，依狀態調整活動 |
| 自我決定論 | 自主：每步可略過、自己選活動；勝任：分級活動；關係：家人分享、社區合作 |
| 行為活化 | 活動後心情評分，週回顧呈現「動完心情變好」的次數，讓長輩看見活動與心情的關聯 |
| 害怕—迴避模式 | 跌倒擔心度每週追蹤；有人陪同的站姿活動作為循序漸進的接觸 |
| 動機式晤談精神 | 聊天先反映感受、開放式問句、肯定、不說教 |
| 文化觀點 | 華人長輩常以身體不適表達心理困擾，因此身體與心情在同一流程中被詢問 |

### 16.3 設計原則

- **AI 是橋梁，不是替代**：聊天中定期鼓勵與家人、朋友、據點連結，避免長輩只依賴 AI。
- **自評不是診斷**：心情與跌倒擔心度只呈現個人趨勢，不設切截分數、不做判讀。正式量表只在研究中由研究人員施測。
- **用詞界線**：對外稱「心理支持」「健康行為促進」，不稱「治療」「諮商」。

### 17.3 葉靈散步遊戲（心動綠洲延伸）
- **花徑**：散步時，每走 40 公尺，路線旁開一朵花。
- **遇見葉靈（安全版）**：每走 0.25 公里、或到公園／據點打卡時遇到葉靈，但**散步中只用語音與震動通知，不需要看手機**；葉靈排隊等待，散步結束、坐下休息時再一一打招呼（輕點一下）。
- **在家也能遇到**：每完成 2 次居家活動，窗邊會來一隻葉靈（蝶蘭仙仙、金桔圓圓），只能做坐姿活動的長輩也能完整參與。
- **葉靈圖鑑**：9 隻以臺灣植物為靈感的原創角色，未遇到時顯示剪影。
- **活的花園**：遇到的葉靈搬進花園，會走動；點一下會說話，台詞包含鼓勵與一個懷舊小問題（例如「你小時候家裡有種茉莉花嗎？」）。
- **場景隨真實時間變化**：清晨、白天、傍晚、夜晚（星星與螢火蟲）；有木棉樹、池塘、小路與長椅。
- **散步明信片**：散步結束後產生圖片（距離、時間、花朵數、遇到的葉靈），可直接分享或存圖後用 LINE 傳給家人。
- **設計原則**：玩法參考「散步收集」與「沿路種花」類型的通用遊戲機制，但角色、名稱、畫面皆為原創；不使用任何既有遊戲的角色、道具或視覺。互動只需輕點，沒有競爭與排名。
