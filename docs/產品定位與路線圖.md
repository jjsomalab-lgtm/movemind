# 心動力 AI｜產品定位與路線圖（回應「樂齡共創 AI 數位健康平台」PRD）

## 一、結論

「AI 樂齡健康促進 × 藝術表達 × 青銀共好數位生態系」適合作為**長期願景**，但不適合在初審前改變作品定位。

| 理由 | 說明 |
|---|---|
| 送件資料已鎖定 | 計畫摘要表與初審簡報已送出、不能抽換，主軸是「運動醫學 × 心理支持 × 打破怕跌倒循環」 |
| 評分重點 | 創意組最重的是創新性（40%）。一個講得深的核心，比六個系統各做一點更有說服力 |
| 驗證成本 | 每多一個系統，就多一組要訪談、測試、審閱的內容；兩人團隊在決審前無法全部驗證 |
| 用詞風險 | 「藝術療癒」「心理健康」容易被視為宣稱療效，應改為「藝術表達」「心理支持」 |

因此建議：**核心不變，把 PRD 的六大系統放進路線圖**，並挑兩項成本低、能強化核心的元素提前做成「輕量版」。

## 二、六大系統對照

| PRD 系統 | 心動力目前狀態 | 建議 |
|---|---|---|
| 01 AI 個人陪伴 | 已有：心情、安全確認、依狀態推薦活動、AI 聊天（APP 與 LINE） | **核心**，持續強化 |
| 02 藝術創作 | 心動綠洲花園有創作元素，但非藝術功能 | 路線圖：試點後評估「色彩花園」（長輩為植物上色、取名） |
| 03 心理幸福 | 已有：活動後心情、跌倒擔心度、動機式晤談風格、危機轉介 | **核心**，對外稱「心理支持」 |
| 04 樂齡遊戲 | 已有：心動綠洲、葉靈散步遊戲、社區合作任務 | **核心**；認知訓練類不納入，避免偏離運動主軸 |
| 05 青銀共創 | 已有雛形：家人分享週報、散步明信片 | **決審可加輕量版**：「家人一起種」——家人用邀請碼看到長輩的花園並送一顆種子 |
| 06 機構管理 | 規格書已規劃據點後台 | 路線圖：試點階段開發 |

## 三、商業模式（與計畫摘要一致，可直接沿用 PRD 的 B2B2C 說法）

- **B2B（主要付費者）**：社區照顧關懷據點、巷弄長照站、日照中心、樂齡學習中心 → 年度授權＋導入訓練
- **B2C（使用者）**：長輩免費使用；家屬加值功能（安心分享、家人一起種）列為後續驗證
- **B2B2C**：政府健康促進計畫、社區組織、企業 ESG 志工專案（青年陪長輩散步、一起收集葉靈）

## 四、路線圖

| 階段 | 時間 | 內容 |
|---|---|---|
| 初審 | 11/7 | 現有原型：安全分級、全活動鏡頭計數、示範動畫、葉靈散步、心理支持設計、LINE 入口 |
| 決審 | 11/21 | 加上：長輩實測數據、真 AI 對話、Google 登入；簡報新增「理論架構」與「產品路線圖」兩頁，PRD 願景放在路線圖 |
| 試點 | 2027 上半年 | 高雄 3–5 個據點；據點後台、家人一起種（青銀共好）、真人示範影片 |
| 擴充 | 2027 下半年後 | 色彩花園（藝術表達）、企業 ESG 青年陪走方案、跨縣市複製 |

## 五、用 Claude Code 開發時

把以下文件依序交給 Claude Code，作為最高層級依據：

1. `AGENTS.md`：開發守則（安全規則不可交給 AI、不可放金鑰、不可使用既有遊戲角色）
2. `docs/SPEC.md`：規格書（安全規則、遊戲規則、資料模型、測試清單）
3. 本文件：產品定位與路線圖

下指令時，一次只給一個任務，例如「依 SPEC 第 15 節第 1 項建立 FastAPI 後端」，並要求它完成後列出改了哪些檔案、如何測試。PRD 中的六大系統，請等決審後依路線圖逐項開發，不要一次全部交辦。
